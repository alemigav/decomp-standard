# REFERENCE_IMPLEMENTATION — how `re2-64-decomp` demonstrates the standard

**Status.** Descriptive. Every statement is a **READ** of the reference project, or a **MEASURED** value
obtained on this machine without the target artifact. The measured state is recorded in
[`ARCHAEOLOGY.md`](ARCHAEOLOGY.md); this document explains what each part *demonstrates* about the standard.

**Target:** Resident Evil 2 for the Nintendo 64 (`NREE`, rev 1 USA). **Scale:** 36 loadable images, 1 947 632
image bytes, 3416 functions over 3678 ranges, 67 MB cartridge. **Repository:** 4020 files, 102 under `tools/`,
229 milestone notes, 305 milestone numbers.

---

## 1. The headline demonstration: four objectives, four honest states

The reference project is the standard's own test case for §0.2 of [`SPECIFICATION.md`](SPECIFICATION.md). It
pursues all four objectives and reports each against its own criterion, with no cross-claim:

| objective | its state | how it is stated |
|---|---|---|
| **Discovery** | complete on the image set | every image byte partitioned into 5 classes; **16.5 % residual published** as `unclassified` and forbidden by mutation from being renamed `data` |
| **Reconstruction** | substantial, unevenly | formats decoded with N/N laws; **3329 / 3416** with every call target resolved; **33** named; **12** behaviourally pinned |
| **Matching decompilation** | barely begun | toolchain identified and reproduced; **15 / 3416** byte-exact; **1** at 226 of 229 |
| **Native porting** | declined | the third layer of the script-VM model is declared out of scope rather than half-built |

The single most valuable thing the reference project does for the standard is state `15 of 3416` next to
`3416 functions` on the same page. A standard without separable objectives would have no vocabulary for why
those two numbers are not in tension.

## 2. Artifact identity and provenance (§1 of the specification)

**Demonstrated:** identity is content, and it is verified before use.

- The artifact's sha256 is committed in `manifests/manifest.json` (`rom_sha256`), and a fetch path verifies it
  **before unpacking anything**.
- Tools that read the artifact print its hash before and after; the project's first written rule is "the
  cartridge is immutable; tools print its sha256 before and after".
- Every one of the 3590 `.c` files carries a four-field provenance header: image + base, address + body extent,
  body sha256, provider record sha256 + provider name and version. A corpus regenerated by a different
  decompiler changes the last line and is therefore distinguishable.
- Target content is refused entry to version control **by bytes**, not by path: a magic match, the artifact's
  hash, or an oversized blob is enough. A single synthetic fixture is allowlisted by name, size-bounded, and
  checked for the magic.

**Limitation demonstrated:** the identification tools themselves have no `--check` mode, so the earliest claims
are the thinnest-gated — a gap the standard should not inherit.

## 3. Inventory (§2)

**Demonstrated:** a partition whose residual is published and whose overlaps are counted.

Measured dimensions: `function_body` 1 210 600 B, `padding` 407 608 B, `unclassified` 321 820 B (16.5 %),
`data_named` 6 640 B, `jump_table` 964 B — summing exactly to 1 947 632 B. Each range names its evidence
(`[start, end, class, source]`). Overlaps are recorded per image rather than reassigned.

Two mutations make the discipline mechanical: `padding` may not overwrite a `function_body`, and the
`unclassified` bucket may not be renamed `data`.

**The defect demonstrated:** the same concept — "bytes inside a known function body" — has two committed values,
1 211 256 and 1 210 600, differing by 656 B because two consumers apply different inputs. Both are correct; no
gate can notice. This is the standard's motivating case for metric *identity*
([`METRICS.md`](METRICS.md) §5.1).

## 4. Structure (§3)

**Demonstrated:** edges carry their evidence, and refusals are published.

- Call graph: 3416 nodes (identity `image:address`, because 28 overlays share a load address), 15 535 edges, each
  graded `jal` / `tail` / `jalr-resolved` / `table-dispatch` / `callback` with a confidence on a documented
  six-value scale.
- **684 of 15 535 edges carry `dst: null` with a reason** rather than an invented table bound, and **250 of 517**
  recorded table bases carry `"bound": null, "bound_src": "none"` rather than a guessed length (measured from
  `manifests/call_graph.json`; the kind split is `jal` 14 669, `jalr-resolved` 382, `table-dispatch` 369,
  `callback` 111, `tail` 4).
- A missed-function census publishes its own residue and evaluates the one survivor, **accepting it without
  adding it** and stating the consequence (24 candidate seeds → 1).
- A refuted heuristic ships with its failure rate in the artifact: the base-derivation self-test matches 1 of 35.

**Demonstrated two-independent-paths rule:** the segmentation rehearsal checks that splat's discovered
boundaries agree with the decompiler's on the same image, and states the principle — "two independent
segmentations agreeing is evidence; one segmentation agreeing with itself is not".

## 5. Formats (§4)

**Demonstrated:** a law with total coverage, and a validator that can fail.

| format | law | coverage |
|---|---|---|
| texture container | `len = 16 + palette·2 + w·h·bpp/8` | 65 / 65 tiles |
| model container | `0x0141` is format version 321, not a magic | relocation law stated and implemented |
| `01 41` family | `word1 = N`, `word2 = filesize − 16N`, payload at `16N` | 355 / 355 blocks, 21 distinct N |
| sample codec | order-2 ADPCM behind a **256-byte shared** codebook | 217 944 / 217 944 groups |
| voice codec | LSB-first bits in big-endian words, 260 bits per block | 588 / 588 clips reconcile |

The validator discipline is the transferable part: `include/re2_formats.h` holds the laws, `tools/t64info.c`
includes it and checks a real block, and `tools/t64_selftest.py` compiles it and runs it **against a corrupted
block too** — "proves it agrees with the cartridge *and* that its checks can fail".

Each of these formats also carries an explicit *refutation* of a tempting structural reading. `01 41`'s units
are not a section table; the container is a flat prologue and what the extra units hold is recorded as a
candidate, not a finding.

## 6. Behaviour (§5)

**Demonstrated:** the harness names what it fakes, and state is addressed by content.

- A partial ISA interpreter whose unimplemented instructions are **faults, not approximations**, and which prints
  its host hooks and stubs on every run so the substituted surface is visible in the output.
- `checkpoint/` — eight files: per-thread CPU and FPU state, a thread table, message queues, memory-region
  hashes, an execution trace, the unresolved-instruction list (currently `[]`, a measured zero), and a digest
  over the other seven. Determinism is one comparison.
- A memory differential that classifies pages into `same` / `harness-zero` / `ares-zero` / `both-differ` and
  states that **only the last two are evidence** — because a page that is zero on both sides proves nothing.
- 12 037 blocks of a hand transcription compared against emulation of the target's own synthesis: **0 samples
  differing**, with the comparison stratum stated (blocks 0–15 of every clip plus whole clips ≤ 96 blocks) and
  the reason the remainder is not affordable recorded.

**Demonstrated honesty about a retirement:** a differential that could not be extended past 158 instructions is
kept in the tree with "RETIRED" in its header and its host findings preserved. Deleting it would delete the
reason.

## 7. Semantics (§6)

**Demonstrated:** an interpretation is attributed, and the weakest form is labelled.

- Opcode names split three ways: 45 opcode keys transcribed from an MIT-licensed table, with source, file and
  method recorded in the artefact's own `attribution` block; 17 inferred by this project and printed with a leading
  `~`; the rest unnamed. (The handover states 43; the count here is read from `fixtures/scd/opcodes.json`, and the
  difference is an unresolved candidate in [`ARCHAEOLOGY.md`](ARCHAEOLOGY.md) §6.)
- The behavioural axis is curated: **12 entries**, each naming the milestone and experiment that pinned it — and
  all 12 **still carry `FUN_` names**, because naming needs evidence of its own. The project's own model was
  refuted by this: it first made validation a rung above naming and returned 0.
- One field is closed as **"Unassigned"** with the reason it needs "a code path, the voice codec, or an
  analogue, not another test".
- A 16-byte parameter record has its four fields and its role measured, and stays **unnamed**, because the
  artifact never labels it.
- The strongest semantic result is a **cross-prediction**: one independently parsed bit predicts another
  independently parsed field on 673 of 674 entries — with the single exception named rather than smoothed.

## 8. Equivalence (§7)

**Demonstrated:** a comparator is itself verified, and a residue is published as a fraction.

- The comparator is proved two ways before use: a self-compare of a built image against the member it came from
  must reach **100.000 %** (stated as "not a tautology, because the two sides are read by different code
  paths"), and a one-word perturbation must be located.
- The toolchain was identified by **refuting** the alternatives rather than by preference: a codegen census found
  `addu rd,rs,zero` 8501 times and `or rd,rs,zero` zero times, which refutes the compiler family that emits `or`.
- 15 functions are byte-exact. The sixteenth is published as **`226 of 229`**, with the three differing words
  decoded (same opcode, same immediates, same base, different destination register), the mechanism identified (a
  `global_alloc` tie-break), **32 alternative spellings compiled byte-identically**, 30 922 permuter iterations
  with zero better-score events, and the reason it is not reachable from source shape.

**Demonstrated beyond the standard's requirement:** the project committed the *wrong* objective of a permuter
experiment (`fixtures/permuter/p6/target-draft.o`, 116 instructions from a draft, against the image's 98) so
that its own retraction stayed reproducible after the original inputs were destroyed. A `.gitignore` exception
carries a paragraph explaining exactly why that file is allowed and the adjacent cartridge-derived object is
not.

## 9. Verification (§VERIFICATION_STANDARD)

This is where the reference implementation is strongest, and where the standard does the least inventing.

**Measured on this machine, without the target artifact:**

```
verifier report — 141b644, cartridge ABSENT
  ci                32 suites / 286 cases  0
  ratchet                             4/4  0
  counts                            25/25  0
  audit                             39/39  0
  admission  gate audit 39/39, 0 vacuous, 0 broken, 107 skipped

VERDICT PASS — every procedure passed and the gate audit is 39/39 with nothing vacuous
coverage partial: cartridge-gated suites SKIPped: any claim that depends on them is INCONCLUSIVE here
```

Every element of the standard's verification doctrine is present in that output: the verdict, the admissibility
tally, the vacuous/broken counts, the skip count, and the coverage caveat in the same breath.

**What the implementation demonstrates about each requirement:**

| requirement | demonstration |
|---|---|
| V1 pinned counts | 73 suites, each with a hand-measured expected case count; a mismatch in either direction fails |
| V2 no silent green | a suite that exits 0 without a verdict tally is `FAIL` |
| V3 skip ≠ pass | `SKIP` printed, counted, grepped, and the full tier **fails** if any appears |
| V4 every gate shown to fail | 146 mutations; a gate is finished only when its mutation is detected |
| V5 positive control | the unmutated tool must succeed in the sandbox first; `BROKEN` otherwise. This recovered **49 of 132** mutations that had never run |
| V6 admissibility first | branch order in a pure function, audit checked before anything else |
| V7 adjudicator self-tested | 8 cases, one per branch, including "a vacuous audit makes a green run INCONCLUSIVE" |
| V8 history pinned | ratchet: registry exact-match, decrease needs an explicit flag, corpus tree hash |
| V9 derived numbers, deleted phrase fails | 31 derivations, 25 sites; deleting a gated phrase fails the gate |
| V10 coverage in the verdict | the output above |
| V12 CI tested without CI | a local linter for the workflow file, 14 cases |

**Measured cost, which is why the tiers exist:** four suites account for the entire gap between a 30-second and
a 12-minute run (`voice sweep` 46 s, `provenance acceptance` 19 s, `routine index bounds` 8 s, `file table`
4.3 s) against a sub-second median for the other 63.

## 10. The record (§EVIDENCE_MODEL)

**Demonstrated:** a retraction is preserved and its cause is stated.

53 rows in a table with fixed columns. Three practices the standard adopts:

1. **The withdrawn claim is quoted verbatim with the milestone that asserted it**, so the retraction is about a
   statement that was actually made.
2. **The superseded value sometimes lives inside the gate**, so the correction is visible in the test rather than
   only in prose.
3. **A flip-flop is recorded as a flip-flop**, with the reason: "each was made on different evidence and the
   later one is not more flattering".

Also demonstrated: **a correction may not move the tally** ("Count unchanged at 101 — a correction should not
move the tally"), and **a claim's non-entailments are a section of the note**, not a caveat in prose.

**And the limit the standard exists to fix:** the record is prose. There is no dependency graph, so a correction
propagates by diligence. Measured consequence: **15 numeric claims contradict the registry**
([`ARCHAEOLOGY.md`](ARCHAEOLOGY.md) §6), one of them eleven lines from a number the gate does check.

## 11. What this reference implementation cannot demonstrate

Stated so the standard does not overclaim from one instance:

1. **Portability.** There is one implementation. The boundary in [`ARCHITECTURE.md`](ARCHITECTURE.md) is
   proposed from a classification of its files, not from a successful second target.
2. **Native porting.** The third layer is out of scope, so §8 of the specification has no demonstration.
3. **A second project's adoption.** No one has adopted this standard. Its requirements are inferred from what
   one project needed, and the inference is untested.
4. **Scale beyond one person.** The project is one author's discipline. Whether the same discipline survives a
   team is exactly what the machinery is for, and it is unproven.
5. **Correctness of the target-specific findings.** This document records what the project asserts and by which
   procedure. It does **not** restate any RE2 fact as established, and on this machine 742 cases and 107 audit
   entries could not run.

## 12. Why this is a good reference implementation

Three properties, each of which a candidate reference implementation should be checked against:

1. **It is complete enough to be wrong.** 305 milestones, 53 retractions, and a corpus that has been through
   several generations of correction. A tidy small example would demonstrate the standard's vocabulary and none
   of its necessity.
2. **It has measured its own defects.** The verification system's failure modes — gates that could not fail,
   mutations that never ran, a verdict that matched a string — are documented with counts. Those instances are
   the entire empirical basis for the standard's requirements, and they are not hypothetical.
3. **It distinguishes what it has not done.** The publishing decision that makes it usable as a reference is
   that its residues are published: 16.5 % unclassified, 15 of 3416 matched, `226 of 229`, 56 gaps with no note,
   742 cases that a fresh clone cannot run.

A reference implementation that only demonstrated correct outcomes would be a worse reference implementation
than one that demonstrates correct *states*.
